# ETL-парсер для создания базы знаний о продуктах

Этот проект представляет собой ETL-скрипт (Extract, Transform, Load) для сбора данных о продуктах с сайта `bast.ru`. Скрипт извлекает информацию о товарах через публичный API, парсит их веб-страницы (включая динамический контент) и PDF-руководства пользователя. В результате работы генерируются структурированные Markdown-файлы (`.md`), предназначенные для использования в качестве базы знаний для ИИ-ассистента или RAG-системы.

## Системные требования

Поскольку парсер использует Playwright и headless-браузер Chromium, для его стабильной работы в Docker-контейнере требуются адекватные системные ресурсы.

- **Операционная система**: Linux (рекомендуется Ubuntu 24.04 LTS).
- **Процессор (CPU)**: **2 ядра** или больше.
- **Оперативная память (RAM)**: **4 ГБ** или больше.
- **Дисковое пространство**: **15 ГБ** или больше (для Docker-образов и самой ОС).

При использовании виртуальных машин (например, через Multipass) необходимо создавать ВМ с указанными выше параметрами:
`multipass launch --name bast-test --cpus 2 --mem 4G --disk 15G`

## Установка и запуск

### Автоматическая установка (рекомендуемый способ)

Для установки или обновления парсера на Linux-сервере выполните одну команду:

```bash
curl -fsSL https://raw.githubusercontent.com/kate-caffe1ne/bast-techsupport-bot/main/install.sh | sudo bash
```

Этот скрипт автоматически:
- Установит `unzip`, `docker` и `docker-compose`, если они отсутствуют.
- Скачает последнюю версию кода и распакует ее в `/opt/bast-parser`.
- Соберет Docker-образ со всеми зависимостями через `docker compose build`.
- Создаст глобальную команду `bast_parser` для удобного управления.

После установки вы можете управлять парсером из любой точки терминала:

- `bast_parser` или `bast_parser start` — Запуск парсера в фоновом режиме.
- `bast_parser logs` — Просмотр логов работы в реальном времени.
- `bast_parser stop` — Остановка работы парсера.
- `bast_parser update` — Обновление кода до последней версии с GitHub.

*Примечание: Сгенерированные файлы базы знаний будут сохранены на хост-машине в директории `/opt/bast-parser/knowledge_base` благодаря volume bind mount в Docker.*

### Ручная установка (для локальной разработки)

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/kate-caffe1ne/bast-techsupport-bot.git
    cd bast-techsupport-bot
    ```

2.  **Создайте и активируйте виртуальное окружение:**
    ```bash
    python -m venv .venv
    source .venv/bin/activate  # Для Windows: .venv\Scripts\activate
    ```

3.  **Установите Python-зависимости:**
    ```bash
    pip install -r requirements.txt
    ```

4.  **Установите браузеры для Playwright:**
    ```bash
    playwright install chromium
    ```

5.  **Запустите парсер:**
    ```bash
    python bast_parser.py
    ```

## Архитектура и инфраструктура

Проект организован с прицелом на дальнейшее масштабирование (добавление БД, Telegram-бота и т.д.):

- **`docker-compose.yml`**: Файл оркестрации контейнеров. В данный момент он настроен на запуск парсера, но уже содержит заготовки (закомментированные секции) для базы данных PostgreSQL и Telegram-бота, что позволяет легко объединить все микросервисы в единую сеть в будущем.
- **`install.sh`**: Универсальный скрипт установки и обновления, работающий поверх Docker Compose.
- **`bast_parser.py`**: Точка входа в приложение парсера. Может быть запущена как самостоятельный скрипт или импортирована как модуль (`run_parser()`) в другие части проекта.
- **`src/bast_parser/`**: Исходный код парсера:
    - `config.py`: Конфигурационные параметры.
    - `api_client/`: Модуль взаимодействия с каталогом API.
    - `parser/`: Логика парсинга HTML (Playwright + BeautifulSoup) и PDF (PyMuPDF).
    - `builder/`: Логика сборки Markdown-файла.

## Технологический стек

- **Python 3.11+**
- **Docker & Docker Compose**: Контейнеризация и оркестрация среды выполнения.
- **httpx**: Асинхронный HTTP-клиент для выполнения быстрых запросов.
- **Playwright**: Асинхронное управление headless-браузером Chromium для парсинга сложных сайтов с клиентским рендерингом (SPA/AJAX) и обхода базовых anti-bot систем.
- **BeautifulSoup4**: Для очистки HTML-дерева от мусора (скрипты, стили, шапки, футеры) и точечного поиска контента по CSS-селекторам.
- **html2text**: Для финальной трансформации очищенного HTML в человекочитаемый Markdown.
- **PyMuPDF**: Для надежного и быстрого извлечения текста из PDF-документов.
- **Pydantic v2**: Для валидации структур данных.
- **aiofiles**: Для асинхронного сохранения файлов на диск.
- **tqdm**: Для красивого отображения прогресс-бара в консоли.

## Особенности реализации
- **Обход блокировок**: Используются специальные флаги Chromium (`--disable-blink-features=AutomationControlled`, подмена User-Agent) и последовательные запросы (`MAX_CONCURRENT_TASKS=1`) для предотвращения блокировок со стороны сервера `bast.ru` (ошибки `502 Bad Gateway`, `net::ERR_TIMED_OUT`, `Target Closed`).
- **Парсинг динамических вкладок**: Скрипт не просто скачивает HTML, а ожидает выполнения JavaScript-прелоадеров на сайте (скрытие надписи "Загрузка..."), чтобы извлечь реальный текст описания и ТТХ из вкладок продукта.

## Устранение неполадок
- **Зависание при запуске браузера**: Если в логах последняя запись — `Browser is disconnected, re-initializing...`, и больше ничего не происходит, это означает, что виртуальной машине не хватает ресурсов (CPU/RAM).
  - **Решение**: Создайте более мощную ВМ. Для `multipass` используйте команду: `multipass launch --name bast-test --cpus 2 --mem 4G --disk 15G`.
- **Ошибка `no space left on device`**: Возникает, если на диске ВМ недостаточно места.
  - **Решение**: Создайте ВМ с увеличенным диском: `multipass launch --name bast-test --disk 15G`.
- **Ошибка `curl: (35) Recv failure: Connection reset by peer`**: Обычно указывает на нестабильное сетевое соединение или проблемы с TLS на стороне сервера/клиента. Скрипт установки был обновлен для автоматических повторных попыток скачивания. Если ошибка повторяется, проверьте сетевые настройки вашей ВМ.
